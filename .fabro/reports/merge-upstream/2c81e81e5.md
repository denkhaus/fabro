## 3. Upstream changes by theme

**a) PR #832 run-intent run-create (dominant):** runs are now created
from registered immutable workflow versions; `fabro_run_create` derives
its target from the selected environment, the parent run's branch (not
its pinned commit), and the workflow's configured `run.scm` repository;
inline workflow paths are validated at their exact entrypoints; workers
inherit targets, standalone calls require explicit ones; run-tool creation
aligns with server admission; 404 when a worker's originating run is gone.
What it means for us: our develop workflow's run-tool usage (spawn_agent /
child runs) now rides the canonical RunIntent path the server enforces —
the engine and the server agree by construction.

**b) PR #855 pebble-pin-main:** pebble repinned after
lithoscomputer/pebble#10; workflow version creation ported to pebble
native tools; workflow packaging shared across callers with bounded depth,
path-only failure surfacing, supplied-config validation. Means for us:
the packaging depth bounds + exact-entrypoint collection make our inline
workflow assets safer to register.

**c) Small-form hardening:** colliding inline workflow paths rejected,
child-target inheritance fixed, supplied workflow source kept out of
failure logs, packaging failure messages precise. Means for us: fewer
silent misresolutions in run-tool target derivation.
