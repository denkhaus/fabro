**a) The driver adoption itself** (RunSandbox, driver crates pinned at rev a92c0db6, providers
routed through Host/Docker/Daytona driver providers, plugin providers, exec policy over the Exec

of driver event ids, Read-tool line numbering + shell quoting moved out of fabro-sandbox.

## 7. Upstream code quality

Small-form commits with contract-first discipline: the protocol enum (SandboxSource) exists and
Daytona implements it while docker explicitly rejects it with a precise error — no silent
fallback. Ownership moved to labels enforced by the driver's ownership scope (attach/delete
refuse unlabeled sandboxes). Test doubles live in the driver's own testing crate; fabro's mocks
are thin accessors over them. Migration discipline: driver events are stored whole; legacy
snapshot event names survive only in the normalization table.

## 8. Overall direction

- The provider layer is now external (sandbox-driver) and plugin-capable; fabro keeps policy
  (exec ladder, git policy, run conventions). Fork work on providers should target the driver
  project, not fabro.
- Image provisioning is provider-owned; fabro-side builds are gone. Our multi-project future
  rides Daytona snapshots (or a driver PR for docker).
- SQLite is the only state that matters; SlateDB shrinks to event log + warm cache.
- Run-event vocabulary is stabilizing around driver events; UI features keying on run-time
  sandbox progress must consume driver events (or the CLI's rendering), not legacy names.
