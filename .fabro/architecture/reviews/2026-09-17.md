## 1. Close the loop-economics feedback loop: an intake regulator at the revisor file stage

**Axis: INTERPLAY (+ OPTIMIZATION).**
**Module**: `.fabro/workflows/revisor/prompts/file.md` (and `analyze.md`, where findings are drafted); the conductor schedule and the develop line are the other side of the loop.

**Interplay**: the revisor files, the develop line drains — each side is healthy alone, together they are a positive feedback loop. Filing scales with painpoints observed (every revision pass files several seeds; survey cluster (1) alone is "dozens of Medium prompt/process seeds"), while draining is hard-capped at one seed per develop run through gate + review + auto-merge. Result: 155 creates vs 80 closes / 7d. Worse, the loop feeds itself: fabro-8776's recorded measurement (2026-09-04..11, from tracker) found **65% of closures were loop self-optimization** — loop friction generates seeds that consume the loop. No module owns the ratio.

**Change**: give the file stage a balance duty and a consolidation rule, as one graph+prompt unit (ADR-0008): (a) per revision pass, new seeds filed ≤ seeds the same pass closed as stale/superseded (the *Bilanzpflicht* option (i) parked in fabro-8776); (b) findings targeting the same file merge into **one multi-arm seed** using fabro-ae74's structured arms schema instead of N siblings. ADR-0002 is untouched — journals stay the only channel; the gate sits at filing, not at reporting.

**Expected effect**: creation couples to drain; the Medium prompt-tweak cluster collapses from dozens of seeds to a handful of arms-list seeds; open count and median age fall directly (the two stagnation inputs).

**Seed coverage**: *new-seed justification —* fabro-8776 named the anti-circling regulator options but closed as consumed with "anti-circling decisions" explicitly left as unfiled carry-overs; tracker search finds no open seed owning intake throttling or per-file consolidation (fabro-aa46 is title-dup detection only, fabro-ae74 the arms format only). **Mark needs-user**: the user parked this decision deliberately (fabro-8776 open decision a).

## 2. Determinize the planner's checkable prose — extend the preflight seam, stop growing the prompt

**Axis: HOT SPOTS (structural cause) + OPTIMIZATION.**
**Module**: `.fabro/workflows/develop/prompts/planner.md` ↔ `.fabro/workflows/develop/scripts/planner-preflight.nu` (+ `dup-run-check.nu`).

**Hot spot & cause**: planner.md is 139 lines of ultra-dense case law where most paragraphs encode *mechanically checkable* invariants: in-flight run/PR exclusion with journal fallback (step 4), stale-basis path resolution (step 3), gate-command ban in briefs (step 7), exact `sd` command forms. Every incident appends a paragraph — that is precisely why survey cluster (1) exists and why prompt-tweak seeds dominate the backlog. The prompt is a shallow module: its interface (one text blob) is as complex as its content, rules have no locality (each new paragraph interacts with all others), and enforcement depends on model compliance — fabro-6e7f's tracker text states it plainly: "Prompt-encoded rules are advisory and drift."

**Deletion test**: deleting a rule-paragraph and re-expressing it as a preflight check *concentrates* complexity into one script interface — the pattern is proven in this very run: the already-landed check ran 1.1s, zero tokens, and handed the planner a 5-candidate verdict table inline (`output.preflight`, run events seq 19–21), where the prompt arm used to cost 93.6s/$0.143 of re-derivation (fabro-a32f basis).

**Change**: adopt a standing rule — *any planner rule naming a greppable invariant lands as a preflight/lint check, not prose* — and migrate the three biggest ones: (a) pre-claim path-resolution of seed-cited anchors (fabro-4c81), (b) in-flight run/PR exclusion with the journal seed-id fallback scripted deterministically (complements engine-side fabro-9372), (c) gate-command ban enforced by the routing output validator (fabro-017f's teeth pattern). Prompts stay project-agnostic per ADR-0013: repo values live in PROJECT_FACTS/scripts, not prose.

**Expected effect**: planner laps stop re-deriving sub-second facts (this run's stale-basis verification of fabro-b7c4 took four probe tool-calls a script could do); the prompt stops growing per incident, shrinking the largest seed cluster at its source; checks become testable code.

**Seed coverage**: *new-seed justification —* the instances are covered piecemeal (fabro-4c81, fabro-9372, fabro-017f, fabro-0da8, fabro-6e7f implementer-side); no open seed owns the planner-side migration policy.

## 6. Revisor coverage is opt-in per `inspects` — make "every journal-producing run is revisable" a linted invariant

**Axis: GAPS and MISCONCEPTIONS.**
**Module**: `.fabro/workflows/revisor/workflow.fabro` (`inspects="develop,merge-upstream"`) and the conductor graph's edges.

**Misconception**: the loop behaves as if every run's painpoints reach a revisor. Actually only terminal, fresh, *inspects-listed*, integrated runs do: conductor painpoints have no consumer (fabro-6ab7), failed develop children soft-exit past the revise leg (fabro-deb5), and the fabro-905d history shows the blind spot compounding — conductor journals silently lost for days with no detector firing anywhere.

**Change**: land fabro-6ab7 (inspects += conductor) and fabro-deb5 (failed-child revise-anyway edge) as the instance fixes, and add a class-level lint to workflow validation: a workflow whose graphs carry the stage-journal hook must appear in some revisor graph's `inspects`, else validation fails.

**Expected effect**: blind spots close structurally; the next 905d-class regression (lost journals, no alarm) becomes a validation error instead of a multi-day forensic find.

**Seed coverage**: fabro-6ab7, fabro-deb5 cover the instances; *new-seed justification —* no seed found in tracker searches for the general inspects-coverage lint.

## 7. One tracker-write seam (and stop paying the 200-row firehose per run)

**Axis: GAPS and MISCONCEPTIONS (+ HOT SPOTS: `.seeds/issues.jsonl`, 95 churn).**
**Module**: tracker writes across `planner-preflight.nu`, `prompts/planner.md`, `closeout.nu`; planner candidate view.

**Misconception**: planner.md line 1 says "you are the only role that writes to seeds" — but four writers exist: the planner (claim, description rewrite, superseded-close exception fabro-d183), preflight (superseded-close, fabro-a32f — this run's output carried a `closed` slot), closeout (approved closes + a growing family of re-file sweeps: fabro-22fa, fabro-ab38, fabro-7aac, fabro-534e), and the revisor (filing). Related hot spot: every `sd update --description` re-emits the whole body wholesale (planner.md step 3) — tracker write amplification (95 churn) and a merge-conflict generator; fabro-23d4's `sd note append` fixes exactly that.

**Change**: make fabro-0da8's deterministic tracker-guard node the single choke point for tracker mutations outside claim/close-of-claimed-seed — preflight and planner superseded-closes and the four closeout sweeps route through one nu module with one test surface (the sweep seeds become features of that module, per ADR-0008 as one unit); land fabro-23d4 (append instead of wholesale rewrite); and land fabro-c3b4 + fabro-11d3 so the planner reads a top-N, failure-class-weighted shortlist instead of this run's `sd ready --limit 200` firehose (200 rows, ~28.8KB into context, run events seq 38). One added guard behavior: flag `in_progress` claims with no live run older than a threshold — the stuck-claim requeue (fabro-986b/ADR-0021 recovers the *line* engine-side; nothing requeues the *seed*).

**Expected effect**: close semantics testable in one place; tracker churn drops; planner context and tie-break cost shrink; the "only writer" claim stops drifting.

**Seed coverage**: fabro-0da8, fabro-23d4, fabro-c3b4, fabro-11d3, fabro-9372, and the sweep family; *new-seed justification for the stale-claim requeue only —* no open seed found for tracker-side requeue of orphaned in_progress claims.
